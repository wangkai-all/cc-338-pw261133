# 判定策略与失败模式

本文档解释 `ledger/evidence.py`、`ledger/collector.py`、`ledger/service.py` 中的判定规则，
以及为什么某些“看起来像删除”的观测**不能**删除资料。

## 1. 一次扫描是什么

一个**批次（batch）** 是在某个时间点对所有已配置地区各执行一次目录扫描。
每个地区的扫描（scan）产出：

* 目录条目列表 + 声明总数；
* 对条目/存量资料的正文探测结果（按预算抽样）。

一个批次内的多个地区扫描共享同一时间点，因此**只算一个证据批次**。

## 2. 目录扫描的完整性

`fetch_listing()` 只有在以下条件全部满足时才返回 `complete=True`：

| 检查 | 失败时 |
|---|---|
| HTTP 200（403/451/5xx 直接终止） | 扫描作废 |
| 页面含 `<!--CATALOG-LIST-->` 与 `<!--CATALOG-END-->` | 扫描作废（可能是 200 错误页或改版） |
| `main[data-total]` 可解析 | 扫描作废 |
| 实际收集条目数 == 声明总数 | 扫描作废（截断/分页错误） |
| 分页签名不重复 | 扫描作废（缓存/循环） |
| `X-Site-Region` == 请求地区 | 扫描作废（错误地区缓存） |
| 列表非空且未异常收缩 | 扫描作废（发布方故障） |

任何一项失败 → `scans.status='anomaly'`、`complete=0`，并自动排入 `rescan_region` 任务。
**这类扫描不会出现在证据聚合里。**

## 3. 单条资料的观测

对每个资料、每个地区扫描，记录一行 `observations`：

| catalog | body | 含义 |
|---|---|---|
| `present` | — | 目录中出现 |
| `absent` | `not_found` / `tombstone` | 目录未出现，正文确认 404 或撤回墓碑 |
| `absent` | `ok` | 目录未出现但正文可读 → **异常**（可能目录缓存问题） |
| `absent` | `blocked` / `error_page` / `incomplete` | 目录未出现但正文不可读 → **歧义** |
| `tombstone` | `tombstone` | 正文明确声明撤回 |

正文只有同时满足以下条件才算 `ok`：

* 含 `<!--ARTICLE-BODY-START-->` 与 `<!--ARTICLE-BODY-END-->`；
* `meta[name=catalog-item]` 与请求 ID 一致；
* 文本长度 ≥ `min_body_bytes`。

截断的正文永远不会更新 `last_content_hash`，也不会被当作“内容变化”。

## 4. 证据聚合

```python
evidence_from_observations(item, observations, scans, policy)
```

1. 按**批次**分组；
2. 批次内：任一地区 `present` → 该批次为可见批次；
3. 批次内：任一观测有 anomaly 或 catalog 为 `unknown/blocked` → 歧义批次；
4. 批次内：所有地区的扫描都完整，且所有地区都 `absent/tombstone` → 缺失批次；
5. 取**最近一次可见批次之后**的连续批次作为“尾段连胜”；
6. 统计尾段内的缺失观测数、地区集合、批次集合、时间跨度。

### 门槛

```python
min_scans=3, min_regions=2, min_scan_batches=2
```

| 条件 | 不满足时 |
|---|---|
| 缺失观测 ≥ 3 | 待复核 |
| 地区 ≥ 2 | 待复核 |
| 批次 ≥ 2 | 待复核 |
| 尾段内无可见 | 恢复或待复核 |
| 尾段内无歧义 | 门槛 +2 次观测 |

### 为什么用“尾段”

历史可见记录不应永久否决当前证据（资料可能在上个月被撤回）；
但尾段内任何一次可见都必须打断连胜（说明资料还在）。这比“全部历史”更贴合事实，
也比“只看最近一次”更抗噪。

## 5. 判定优先级

```
来源通知 > 人工冻结 > 达标证据 > 最近可见 > 最近歧义 > 证据不足
```

* **来源通知**：直接撤回，无需扫描证据；重复通知幂等；正文仍可见时标记需关注。
* **人工冻结**：保持待复核，不自动撤回也不自动发布。
* **达标证据**：自动撤回。
* **最近可见**：待复核 → 恢复；自动撤回 → 保持撤回并标记需关注（粘性）。
* **最近歧义**：待复核，不删除。
* **证据不足**：待复核。

## 5.1 下游的两种“撤下”

台账状态与下游状态不是一一对应，因为下游需要立即保守：

| 台账状态 | 下游事件 | 下游状态 | `permanently_restricted` |
|---|---|---|---|
| `active` | `publish` / `update` | published | false |
| `quarantined`（暂时不可见） | `withhold` | withheld | **false** |
| `retracted`（撤回） | `retract` | withheld | **true** |

* `permanently_restricted=false` 的撤下是**临时**的：条目回到完整扫描后，
  台账恢复为 `active`，普通 `publish` 事件即可重新发布。
* `permanently_restricted=true` 的撤下是**永久**的：任何不带 `allow_restore`
  的 `publish`（包括序号更新的扫描事件）都会被拒绝，只有运营人工恢复可解。
* `update` 事件只携带内容，不能改变发布权限；它永远不会解除撤下。

## 6. 误删风险与控制

| 风险 | 机制 |
|---|---|
| 站点长期屏蔽同一资料 | 正文墓碑页是强信号；地区屏蔽不计入证据；人工恢复保留审计 |
| 目录整体缩水 | `population_ratio < 60%` 时 `anomaly_heavy=True`，门槛 +2 |
| 缓存/路由错误 | `X-Site-Region` 校验；错误地区扫描作废 |
| 截断伪装成“条目消失” | 声明总数校验；不匹配即作废 |
| 200 错误页伪装成正常 | 边界标记校验；缺失即作废 |
| 通知误投 | 来源允许列表；`notice_id` 幂等；payload 哈希留档 |
| 下游复活 | 序号单调；撤回只能由 `allow_restore` 解除；临时撤下与永久撤回分开记录 |
| 陈旧扫描事件 | 发件箱幂等键 + 下游序号拒绝；`update` 事件不能解除撤下 |

## 7. 成本

* **扫描**：每地区每批次 `ceil(总数/页大小)` 次目录请求。
* **正文**：每地区每批次最多 `body_budget` 次（默认 24），其中约 1/3 轮换覆盖存量，
  其余优先新条目与需关注条目。
* **判定**：本地 SQLite 读写，无网络。
* **下游**：每条状态变化一条事件，失败指数退避，超过 10 次进入 `dead`。

## 8. 未覆盖的情况

* 站点改版导致边界标记变化：扫描会持续作废并补扫，需要更新解析器。
* 目录分页在两次请求之间变化：声明总数校验会捕捉到，作废并补扫。
* 同一资料在多个地区有不同正文：目前只保存最后抓取的快照，不按地区比对内容差异。
